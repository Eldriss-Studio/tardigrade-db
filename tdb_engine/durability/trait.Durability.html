Expand description

The durability boundary contract.

Every concrete durability impl provides the same four observable facts: the current durable offset, the current issued offset, a way to bump issued, and a way to block until durable catches up to a target. Engine consumers depend on this trait so a future replicated / async-batched / metric-instrumented impl can plug in without touching the engine’s write or read paths.

Object-safe by construction — methods are &self, no generics, no Self return types. Stored in the engine as Arc<dyn Durability + Send + Sync>.

Source

fn current_durable(&self) -> u64

Current durable offset — every write at or below this offset has reached stable storage.

Source

fn current_issued(&self) -> u64

Current issued offset — every accepted write up to and including this offset is in flight or durable.

Source

fn issue_one(&self) -> u64

Atomically bump issued and return the new value.

Called from every write path the moment the engine accepts the write. Distinct from durability — the write may sit in a buffer for an arbitrary time before its fsync lands.

Source

fn publish_durable(&self, offset: u64)

Mark every issued offset up to and including offset as durable. Idempotent: a second call with the same or lower value is a no-op.

Implementations must clamp offset to current_issued() so durable <= issued is an unconditional invariant.

Source

fn wait_durable( &self, target: u64, deadline: Duration, ) -> Result<(), WaitTimedOut>

Block until current_durable() >= target or deadline elapses.

Callers should drop the engine lock before invoking this so writers can advance the offset concurrently.

§Errors

Returns WaitTimedOut if current_durable() does not reach target within deadline.
